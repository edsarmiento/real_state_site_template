Variables (reemplazar)
----------------------

  <slug>              layout_key en API/Ops, minusculas (ej. beige)
  <THEME_NAME>        nombre en codigo / SiteThemeName (ej. beige; puede diferir del layout_key)
  <ThemeName>         PascalCase para componentes (ej. Beige)
  <THEME_LABEL>       etiqueta humana (ej. Beige — catalogo calido)
  <REFERENCE_THEME>   theme a copiar estructura: default | luxury
  <STYLED_LAYOUT>     true | false — usar styledLayout en search/cards/forms compartidos
  <PALETTE_NOTES>     notas de diseno (colores, tipografia, hero, etc.)

Contexto
--------

Monorepo Real State. Trabaja SOLO en:

  real_state_site_template/  (Next.js App Router, puerto dev 3002)

1 deploy = 1 inmobiliaria (ACCOUNT_ID + API_URL). Marca, layout, idiomas y dominio
vienen de SiteConfig via GET /api/public/site_config?account_id=.

Objetivo: cuando Ops guarde layout_key: "<slug>", el template renderiza el theme
<THEME_NAME> en / y /inmueble/[slug].

Lee:
  - real_state_site_template/AGENTS.md
  - real_state_api/BUSINESS_RULES.md — SiteConfig


Arquitectura (no romper)
------------------------

  src/app/page.tsx -> resolveSiteThemeFromConfig() -> theme.Catalog
  src/app/inmueble/[slug]/page.tsx -> theme.ListingDetail

Contrato: src/themes/theme-types.ts (CatalogThemeProps, ListingDetailThemeProps).

Reglas:
  - Server Components; sin fetch de listings dentro del theme.
  - i18n: getSiteUi(lang) + site-i18n.ts.
  - Marca: getSiteUi().config (SiteConfig via getResolvedSiteConfig).
  - Theme = skin: recibe valores y pinta. Inquiry, WhatsApp, specs y href
    salen de ListingInquiryForm, ListingWhatsAppButton, publicListingCardModel,
    listingPublicSpecsLocalized. NO copiar esos flujos en src/themes/<slug>/.


Alcance v1 — theme <ThemeName>
------------------------------

Identidad visual:
  <PALETTE_NOTES>

Minimo obligatorio en src/themes/<slug>/
----------------------------------------

  <slug>-catalog.tsx           OBLIGATORIO — pagina /
  <slug>-listing-detail.tsx    OBLIGATORIO — pagina /inmueble/[slug]

Recomendado:
  <slug>-legal-page.tsx        legales con el mismo shell
  <slug>-catalog-hero.tsx      solo si el hero no va inline en catalog

Catalog debe incluir:
  - SiteHeader / SiteFooter (prop lang)
  - Hero con siteName, siteTagline (getSiteUi)
  - PublicCatalogSearch + PublicListingCard (styledLayout segun <STYLED_LAYOUT>)
  - Empty state / error catalogo (ui.dict.results.*)
  - Barra admin -> /login
  - Wrapper: data-site-theme="<slug>"

Listing detail debe incluir:
  - Paridad funcional con default-listing-detail (galeria, specs, inquiry, WhatsApp, maps)
  - listingUrl con listingPublicUrl(slug, ui.config.siteOrigin, localizedHref(...))
  - ListingInquiryForm + ListingWhatsAppButton (classNames del theme; sin form propio)
  - listingPublicSpecsLocalized / publicListingCardModel; sin *-specs.ts del theme


Cableado obligatorio (template)
-------------------------------

  1. theme-types.ts          — "<THEME_NAME>" en SiteThemeName
  2. theme-registry.ts       — entrada <THEME_NAME>: { Catalog, ListingDetail }
  3. resolve-site-theme.ts   — layout_key "<slug>" -> "<THEME_NAME>" en themeNameFromLayoutKey()
  4. site-config-types.ts    — "<slug>" en SiteLayoutKey
  5. resolved-site-config.ts — "<slug>" en LAYOUT_KEYS

Recomendado:
  6. Legales: aviso-de-privacidad, terminos, cookies — rama theme.name === "<THEME_NAME>"
  7. AGENTS.md — fila en tabla layout_key -> theme

NO modificar app/page.tsx ni app/inmueble/[slug]/page.tsx (salvo bug).
NO usar site-config.ts legacy. NO fetch al Rails desde el browser.
